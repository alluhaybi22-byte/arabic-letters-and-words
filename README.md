# لغتي الجميلة — الاختبار التشخيصي الشفوي

تطبيق Windows عربي للمعلم لتقييم قراءة طلاب الصفوف الأولية، بواجهة RTL وخط
Arial ومادة قراءة كبيرة واضحة. هذا الإصدار ينقل النسخة التجريبية المختبرة
1.3.4 إلى المستودع ويجهز مثبت EXE.

محرك التشغيل مثبت على Electron 44.5.1، مع تحديث الاعتمادات المتأثرة بفحص
الأمان. يشمل بناء Windows فحص npm audit قبل إنشاء المثبت.

## الوظائف

- سبعة مستويات: الحروف، أشكال الحروف، الحروف بالحركات، كلمات الفتح، الكلمات
  المشكلة، الكلمات، والجمل. يبقى منطق التقييم والمؤقت كما في النسخة التجريبية.
- تقييم بنقرة واحدة، وحفظ المسودة والنتائج محليًا، والتنقل بين الطلاب.
- استيراد PDF وDOCX وXLSX، بما يشمل الجداول والأعمدة والأوراق المتعددة،
  ثم مراجعة الأسماء قبل اعتمادها. منع تكرار اسم الصف مع السماح بتحديث ملفه نفسه.
- سجل النتائج: مجلد صف، ثم مجلد مستقل لكل اختبار بتاريخ إجرائه، ثم نتائج الطلاب.
  تعرض النتائج القديمة في الأرشيف؛ لا يمكن استعادة حدود الجلسات القديمة التي
  لم تكن تحفظ سابقًا، لذا تجمع بحسب الصف والتاريخ والمستوى.
- تقارير الفرد والصف، ومعاينة طباعة Windows مستقلة، وحفظ PDF بمقاس A4.
- حذف اختيار نوع الصعوبة من الاختبار، وحذف عمودي المدير وولي الأمر من التقرير
  الشامل، وحذف المدينة وهاتف المدرسة من نموذج بيانات المدرسة.

## التثبيت

ملف البناء: `Lughaty-Oral-Diagnostic-Setup-1.3.4.exe`، لنظام Windows x64.
المثبت يتيح اختيار المجلد وينشئ اختصارات، وإزالة البرنامج تبقي بياناته المحلية.
تبدأ النسخة الجديدة دون صفوف أو طلاب أو نتائج أو بيانات مدرسة محفوظة.
تستخدم ملف تعريف مستقلًا `lughaty-oral-diagnostic-clean`، ولا تنسخ بيانات
النسخ السابقة تلقائيًا ولا تحذفها. يستورد المستخدم الصفوف بنفسه؛ تبقى بياناته
التي أدخلها في هذه النسخة عند إعادة تشغيلها وتحديثها وإزالة البرنامج.

**حالة التوقيع: لم تصدر بعد شهادة موثوقة لهذا المشروع.** لا يعني نجاح البناء
أو وجود SHA256 موافقة Windows Defender أو SmartScreen. مسار SignPath المجاني
قيد التجهيز، ويحتاج تقديم المالك وقبول الجهة. التفاصيل في [إجراءات التوقيع](docs/SIGNING.md).

## التشغيل والبناء

على Windows، باستخدام Node.js 24:

```powershell
npm ci
npm run verify
npm test
npm start
npm run dist
```

ينشئ الأمر الأخير المثبت في `release/` دون نشر إصدار عام.
تنفذ `.github/workflows/windows-installer.yml` البناء على Windows، ثم تثبت
ملف EXE وتشغل اختبارات الواجهة، وتولد PDF فعليًا، وتختبر بقاء البيانات بعد الإزالة.
تنزيلات البناء وأدلة الاختبار تظهر ضمن Artifacts الخاصة بالتشغيل الناجح في Actions.
اختبار طابعة فعلية يحتاج جهاز المستخدم وبرنامج تشغيل الطابعة.

## ملفات المشروع

- `index.html`: الواجهة ومنطق التقييم الموجود؛ لم يُعد بناء المشروع من الصفر.
- `main.js` و`print-bridge.js`: نافذة التطبيق ومسار المعاينة والطباعة والحفظ.
- `profile-policy.js`: مساحة بيانات مستقلة، دون استعادة تلقائية من النسخ القديمة.
- `vendor/` و`brand/`: المكتبات المحلية والهوية البصرية المستخدمة.
- `smoke.cjs` و`tests/`: اختبارات المنطق والاستيراد والطباعة والتثبيت.

لا تضم حزمة التشغيل ملفات مرجع Figma أو بيانات طلاب حقيقية أو مفاتيح API.
ترخيص كود المشروع MIT كما هو معلن في package.json؛ تحتفظ المكتبات الخارجية
بتراخيصها. راجع [سياسة الخصوصية](PRIVACY.md).

## التحديث من داخل التطبيق

في بيانات المدرسة والإعدادات يظهر إصدار البرنامج وزر التحقق من التحديثات،
ثم تنزيل التحديث، ثم تثبيت وإعادة التشغيل بعد تأكيد المستخدم. لا يثبت عند
الإغلاق العادي ولا يسمح بالرجوع لإصدار أقدم أو بالتثبيت أثناء وجود مسودة
اختبار أو مراجعة أسماء غير مكتملة. بيانات الطلاب تبقى في ملف التعريف نفسه.

مصدر التحديث ثابت على إصدارات مستودع alluhaybi22-byte/arabic-letters-and-words.
لا يتضمن البرنامج مفتاح GitHub أو خدمة رفع بيانات الطلاب. يتحقق electron-updater
من SHA512 للملف. النسخة الحالية غير موقعة؛ لا توجد هوية ناشر مشفرة معتمدة بعد.

لتفعيل قناة التحديث يجب نشر المثبت وlatest.yml وملف blockmap المتوافقين
في GitHub Release بعد موافقة المالك. لا تنشر workflow إصدارًا تلقائيًا،
والبناء يستخدم --publish never. راجع [إجراءات نشر التحديث](docs/UPDATES.md).
النسخ السابقة 1.3.3 وما قبلها تحتاج تثبيت هذا الإصدار مرة واحدة لإضافة المحدث.
