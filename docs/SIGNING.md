# توقيع نسخة Windows

الحالة الحالية: **غير موقعة بشهادة ناشر موثوقة، وطلب SignPath لم يقدّم ولم يقبل بعد**.
لا توجد شهادة أو أسرار توقيع في المستودع. لا تستخدم شهادة ذاتية التوقيع لإيهام
المستخدم بوجود موافقة من Windows، ولا تطلب تعطيل برنامج الحماية.

## المسار المجاني المختار

SignPath Foundation يقبل بعض المشاريع المفتوحة المصدر وفق شروطه ومراجعته.
الشهادة المقدمة في هذا المسار باسم المؤسسة، وليست شهادة شخصية باسم المعلم.
قبول المشروع والطلب لا يمكن ضمانه. المتطلبات المنشورة تشمل ترخيصًا مفتوحًا،
إصدارًا ثنائيًا متاحًا سابقًا، وصفًا لوظائفه، وبناءً يمكن التحقق من مصدره، ومصادقة
متعددة العوامل للمسؤولين وتحديد أصحاب حق اعتماد طلبات التوقيع.

تم تجهيز README وMIT وPRIVACY واختبارات وبناء Windows. توجد مسودة طلب في
[SIGNPATH-APPLICATION.md](SIGNPATH-APPLICATION.md)، مع البنود التي يجب أن يتحقق
منها مالك المشروع. نشر Release عام لم ينفذ؛ يبقى خاضعًا لموافقة المالك.

بعد قبول المشروع، خزّن بيانات الاتصال في GitHub Secrets، واضبط مشروع وسياسة
التوقيع لدى الجهة. يستهلك التكامل الرسمي Artifact من GitHub Actions على أجهزة
GitHub المستضافة، ثم يعيد الملف الموقع بعد الاعتماد. ينبغي توقيع ملف التطبيق
ومزيل التثبيت قبل التجميع، ثم المثبت النهائي؛ توقيع غلاف NSIS وحده لا يثبت
أن الملفات الداخلية موقعة. يعتمد التنفيذ النهائي على إعدادات الجهة المعتمدة.

لا يفعّل هذا الفرع طلبات توقيع غير مهيأة ولا يعلن موافقة لم تصدر. يسجل البناء
الحالي `Get-AuthenticodeSignature` وSHA256 للمثبت. عند وصول ملف موقع، يجب التحقق
من `Status = Valid`، والناشر الفعلي، والختم الزمني، والتطبيق ومزيل التثبيت أيضًا.

SmartScreen يعتمد على السمعة بالإضافة إلى التوقيع؛ قد يحذر من ملف جديد حتى
بشهادة موثوقة. برنامج مكافحة الفيروسات يفحص سلوك ومحتوى البرنامج بصورة مستقلة.
إذا ظهر اكتشاف محدد، احفظ اسم الكشف وSHA256 وقدّمه للمورّد للمراجعة؛ لا توجد
«رخصة عامة» تمنع جميع برامج الحماية من فحص التطبيق.
