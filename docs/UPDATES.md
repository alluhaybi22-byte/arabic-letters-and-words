# تحديث البرنامج من داخل التطبيق

في الإعدادات وبيانات المدرسة تظهر النسخة الحالية وأزرار التحقق من التحديثات،
وتنزيل التحديث، ثم تثبيت وإعادة التشغيل. لا يوجد تثبيت تلقائي عند إغلاق
البرنامج، ولا تنزيل بمجرد فتحه. يجب حفظ الاختبار وإنهاء مراجعة الأسماء قبل
التثبيت، ويطلب البرنامج تأكيدًا صريحًا قبل إغلاقه.

النسخ 1.3.3 وما قبلها لا تحتوي على المحدث؛ تحتاج تثبيت 1.3.4 مرة واحدة.
بعدها تنزل الإصدارات التالية وتثبت من داخل البرنامج، دون تنزيل المثبت يدويًا
من المحادثة أو صفحة المستودع. الاتصال بالإنترنت مطلوب للحصول على التحديث.

تبقى مساحة البيانات `lughaty-oral-diagnostic-clean` ثابتة بين الإصدارات.
لا يرسل طلب التحديث أسماء الطلاب أو نتائجهم، ولا تنقل النسخة كشوفًا من
ملفات تعريف النسخ القديمة تلقائيًا.

## ملفات النشر المطلوبة

المصدر ثابت على إصدارات المستودع العام:
`alluhaybi22-byte/arabic-letters-and-words`.

ينتج بناء الإصدار 1.3.4 ملفات:

- `Lughaty-Oral-Diagnostic-Setup-1.3.4.exe`
- `Lughaty-Oral-Diagnostic-Setup-1.3.4.exe.blockmap`
- `latest.yml`
- `SHA256SUMS.txt` وملفات حالة التوقيع للمراجعة.

يجب نشر الملفات الثلاثة الأولى معًا في Release عام غير تجريبي باسم
`v1.3.4`، ونسخ كل ملفات النسخة نفسها دون إعادة تسمية أو تعديل بعد توليد
التجزئات. للإصدار اللاحق يرتفع رقم النسخة، وتُنشر ملفاته وlatest.yml الموافق
له؛ يستبعد المحدث الإصدارات الأقدم والإصدارات التجريبية.

**لا ينشر البناء أو GitHub Actions Release تلقائيًا**؛ يبقى `--publish never`.
لم يُمنح الإذن بنشر Release في هذه المهمة؛ تُجهز الحزمة للمراجعة أولًا.
قبل نشر أي إصدار يجب الحصول على موافقة المالك وفق تعليماته القائمة.

في غياب إصدار أو ملف قناة التحديث تظهر رسالة مفهومة، ويستمر استخدام البرنامج.
الأخطاء في الاتصال أو تنزيل ملف غير سليم لا تغلق التطبيق ولا تثبت الملف.

## سلامة التحديث

يستخدم electron-updater 6.8.9 للتحقق من SHA512 المعلن في بيانات الإصدار.
المصدر العام يعمل عبر HTTPS ولا يحتاج مفتاح GitHub مضمّنًا في التطبيق.
لا تقبل واجهة renderer رابط تنزيل أو مسار مثبت أو تغيير مصدر التحديث.
رسائل التحديث تقبل فقط من الإطار الرئيسي للصفحة المحلية المعتمدة.

النسخة غير موقعة بشهادة ناشر موثوقة حتى الآن، ولا تعادل التجزئة توقيع ناشر.
الثقة الحالية مرتبطة بسلامة حساب GitHub والمصدر الثابت، واعتماد SignPath
لم يصدر. عند اعتماد شهادة التوقيع تضبط هوية الناشر لتفعيل مطابقة توقيعه
في المحدث؛ لم تُعطل آلية التحقق من التوقيع ولم تستبدل بقبول جميع الشهادات.

## اختبار Windows

يبني الاختبار إصدار 1.3.4 المستهدف ونسخة اختبارية خاصة تحمل رقم 1.3.3
من شيفرة المحدث نفسها. الأخيرة ليست مثبت 1.3.3 الذي وزع سابقًا، ولا تنشر.
بعد تثبيتها تستورد بيانات اصطناعية، ثم تُرقّى من داخل التطبيق إلى 1.3.4
عبر خادم اختبار على loopback. يختبر رفض محتوى لا يطابق SHA512، والإلغاء،
ومنع التثبيت أثناء المسودة، والتثبيت الفعلي وإعادة التشغيل وبقاء السجل.
تغيير المصدر إلى loopback موجود في مشغل الاختبار فقط ولا يُضمّن في المثبت.

بعد الموافقة على النشر يختبر وصول القناة العامة من جهاز المستخدم؛ نجاح
قناة الاختبار الخاصة لا يعني أن Release عام قد نشر أو وصل إلى المستخدمين.
